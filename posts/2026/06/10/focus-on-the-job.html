工作中最稀缺的是什么？

程序员最大的敌人是什么？

复杂度。

程序员最稀缺的是什么？

注意力。

专注是一种非常稀缺的资源。

为什么这么说？

假设你现在使用 Agent 进行 coding，同时交给他 1、2、3、4 四件事情，这四件事情并没有任何关系，你会得到一个非常差的结果。

为什么呢？因为 Agent 也会因为注意力的原因出现幻觉。

而如果你一件一件事情交代给他去做，你会发现效果比之前好很多。因为 Agent 在每一步都只关注一个事情。

假如你用 plan 的模式，让 Agent 先按照需求去做分析、做计划，然后落地成可执行的计划。你让 Agent 再按照计划一步步去执行。你会发现效果更好。

人跟 Agent 协作编码为什么对注意力是一种伤害？

因为 Agent 是需要思考的，这几十秒或者几分钟之内，人其实能去做什么呢？

大部分人可能切到别的工作事项上，或者刷刷网页，或者打开手机。

这种切换和思维的中断，对一个人的注意力影响是非常大的。

我们将很难进入之前手工编码时代的那种心流的状态。

这种断断续续的工作模式将会导致你的工作产出被碎片化。再加上 Agent 本身可能存在幻觉、执行不到位、指令服从度不高，那么整体产出的东西可能并不是你预期的那样。

所以我们应该怎么做？

我的建议是在开始之前就对最终的产出有一个具象的预期。你希望得到的东西符合你预期的产出，通过什么方式实现，有什么要求等等。这些都想清楚之后，再开始通过与 Agent 协作来完成工作。

在这期间，强烈不建议切出去刷刷网页、看看手机之类的，而是建议查看 Agent 的思考过程，查看中间的产出物，如果有幻觉或者思路问题，及时打断。

或者你已经有了一个完整的工作流，交代给 Agent 的一件事，它可以无人值守，从头做到尾，你只需要关注最终的 code review 即可。
